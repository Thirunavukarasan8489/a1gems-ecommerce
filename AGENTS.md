# AGENTS.md — A1 Gems Platform Context & Working Rules

This file gives any coding agent (Claude Code, Cursor, Copilot, etc.) the context needed to work on the A1 Gems codebase consistently. 

The codebase is treated as **two visually distinct applications sharing one backend**: the **Public Website** (brand-led, Plum/Gold/Emerald palette) and the **Admin Panel** (functional, data-dense, neutral palette modeled on a POS/inventory admin template). Components must NOT be shared across these two surfaces — build two separate component libraries.

---

## 1. Tech Stack Assumptions & Agent Working Rules

- **Framework:** Next.js (App Router) — route groups `(public)` and `(admin)`
- **Database:** MongoDB (Mongoose or native driver), with MongoDB **transactions** for multi-step writes and **TTL indexes** for temporary cart expiry
- **Validation:** Zod on every server action / API route
- **Media:** Cloudinary (metadata + URLs stored in MongoDB)
- **Auth:** Session/JWT-based, role-based access control (RBAC) for admin
- **Payments:** Gateway-agnostic (UPI, Card, Net Banking, COD, Bank Transfer) — verify via **webhook**, never trust client-side success alone
- **Middleware Convention:** Next.js 16.3+ has deprecated the `middleware.ts` file convention. Always use `proxy.ts` instead for middleware logic.
- **Transactions:** Any operation that changes both an order and inventory must be wrapped in a **MongoDB transaction**.
- **Shipping / Taxes:** Never hardcode shipping fee, tax rates, or COD eligibility rules — these must come from **Admin Settings**.
- **Forms & Mutations:** Use `react-hot-toast` (preferably `toast.promise`) for all server action feedback. Do not use local error state in forms.
- **Deletions:** Always use the reusable `DeleteConfirmButton` component for delete actions in admin tables.
- **Slugs:** Slugs are auto-generated by the backend upon creation. Do not include slug inputs in frontend forms.

## 3. UI/UX Design System — Admin Panel

Design intent: dense, scannable, functional — modeled structurally on a **POS Admin Dashboard**. Use a **neutral admin palette** (grays/blues/whites), intentionally distinct from the public Plum/Gold/Emerald brand tokens so admins never confuse the two surfaces. Reserve small brand accents (e.g. Gold for a logo mark) only, not for functional UI.

---

## 4. Reusable Component Library Architecture

Two independent component sets. Do not import public components into admin routes or vice versa. Shared logic (non-visual) can live in `components/shared/` or `lib/`.

- `components/public/`: Premium, editorial, conversion-focused, imagery-led. Built on the Plum/Gold/Emerald tokens.
- `components/admin/`: Dense, functional data tables, kpi cards, sidebars, neutral palette.
- `components/shared/` or `lib/`: Non-visual logic (`formatCurrency`, Zod schemas, `availabilityCalc`, status mappers). All status displays must read from centralized status-config maps.

## 6. Public Website Flow

### 6.1 Project Overview
The platform supports two primary customer actions on every product:
Product
  |-- Enquire --> Lead
  |-- Add to Cart --> Order
Every product therefore supports one of three purchasing modes: ENQUIRY ONLY, BUY ONLY, or BUY + ENQUIRY.

### 6.2 Customer Types
A customer can purchase as a Personal Customer or a Business Customer. Having a customer account is optional — the platform supports Guest Checkout, using a temporary cart before order creation.

Business users can purchase with the following details:
- Business Name, Contact Person, Business Address, Billing Address, Shipping Address
- If GST registered: GSTIN, Legal Business Name, GST Address
- If not GST registered: basic business details are captured as a Normal Business Purchase.

### 6.3 Public Website Site Map
Home -> Collections -> Products -> Gemstone Guides -> About -> Contact -> Cart

### 6.4 Homepage Flow
Announcement Bar -> Hero Banner -> Trust Highlights -> Promotional Banners -> Featured Categories -> Featured Products -> Why Choose A1 Gems -> Gemstone Showcase -> Bracelet Showcase -> How It Works -> Consultation CTA -> About Section -> Testimonials -> FAQ -> Final CTA

### 6.5 Product Discovery Flow
Homepage -> Category -> Product Listing -> Product Detail
(Alternative: Search -> Search Results -> Product Detail)

### 6.6 Product Purchase Types
- **Enquiry Only**: Product -> Enquire Now -> Lead Form -> Lead Created
- **Buy Only**: Product -> Add to Cart -> Cart
- **Buy + Enquire**: Both options available.

### 6.7 Enquiry Flow (Customer-Facing)
Product -> Enquire Now -> Lead Form -> Customer Information (Name, Phone, WhatsApp, Email, Location) -> Enquiry Information (Product, Category, Message, Source) -> Submit -> Validate -> Create Lead -> Admin Notification

### 6.8 Cart Flow
Because guest checkout is supported, carts are tracked without an account:
Browser -> Temporary Cart ID -> Cookie -> MongoDB Temporary Cart
Cart document fields: Product ID, Quantity, Price Snapshot, createdAt, expiresAt. Expired carts are removed using a MongoDB TTL index.

Pre-checkout validation: Cart -> Validate Products -> Validate Prices -> Validate Quantity -> Validate Stock -> Validate Product Status -> Checkout.

### 6.9 Checkout Flow
Cart -> Checkout -> Customer Information -> Purchase Type -> Address -> GST / Business Information -> Shipping -> Order Summary -> Payment -> Confirmation

- **Customer Information (Guest Checkout)**: Name, Phone, Email
- **Personal Checkout**: Personal -> Customer Information -> Shipping Address -> Billing Address -> Shipping Fee -> Order Summary -> Payment
- **Business Checkout**: Business -> Company Information -> GST Registered? (Yes/No) -> Addresses -> Shipping Fee -> Tax Calculation -> Order Summary -> Payment

### 6.10 Address & Shipping Flow
The system always supports a Shipping Address and a Billing Address. If billing is the same as shipping, the shipping address is reused.
Shipping is currently fixed-price. The exact amount should be configurable from Admin Settings.

### 6.11 Inventory Availability (Customer-Facing)
Checkout -> Stock Check -> Available?
- NO -> Checkout Blocked
- YES -> Reserve Stock -> Create Pending Order -> Payment

### 6.12 Payment Flow
Supported payment methods: UPI, Card, Net Banking, COD, Bank Transfer.
- **Online Payment**: Reserve Inventory -> Payment Gateway -> Gateway Response -> Webhook Verification -> Payment Success -> Order Confirmed
- **Bank Transfer**: Create Order -> Payment Pending -> Customer Transfers Money -> Admin Verifies -> Payment Confirmed
- **COD**: Select COD -> Check COD Eligibility (PIN, Value, Product, Customer) -> Create Order -> Confirm Order

### 6.13 Order Lifecycle (Customer View)
PAYMENT_PENDING -> CONFIRMED -> PROCESSING -> PACKED -> SHIPPED -> OUT_FOR_DELIVERY -> DELIVERED
(Exceptions: PAYMENT_FAILED, CANCELLED, DELIVERY_FAILED, RETURNED)

### 6.14 Post-Delivery Flows
- **Cancellation**: Customer -> Cancel Order -> Check Eligibility -> Cancel Order -> Release Inventory -> Payment Refund? (Only for prepaid).
- **Return**: Delivered -> Customer Requests Return -> Reason -> Eligibility -> Admin Review -> Pickup -> Product Received -> Inspection -> Return Approved -> Refund
- **Refund**: Return Approved -> Refund Created -> Refund Processing -> Payment Provider / Bank -> Refund Completed (PENDING, PROCESSING, COMPLETED, FAILED)

## 7. Admin Panel Flow

**CRITICAL WORKING RULE:** When building or modifying any Admin Panel screen, you MUST read the corresponding section in `A1-GEMS-Admin-Panel-Screen-Wise-Specification.md` for exact field requirements, actions, filters, and layouts before writing code.

### 7.1 Admin User Roles
- Super Admin
- Content Manager
- Lead Manager
(Add commerce permissions to these rather than creating new roles).

### 7.2 Lead Management Flow
Lead Lifecycle: NEW -> CONTACTED -> FOLLOW_UP -> QUALIFIED -> CONVERTED (or CLOSED, SPAM).
Lead Detail includes: Customer details, Enquiry details, Management (Status, Assigned To, Notes, Follow-up), Actions Taken (Call, Email, Note).

### 7.3 Order Processing Flow (Admin)
New Order -> Payment Verified -> Order Confirmed -> Admin Processing -> Inventory Finalized -> Packing -> Shipment Created -> Courier Tracking -> Shipped -> Out for Delivery -> Delivered.

### 7.4 Catalogue Management Flow
**Product Admin Fields**:
- Basic: Name, Slug, Category, Short Description, Description
- Pricing: Selling Price, Compare Price
- Inventory: SKU, Stock Quantity, Reserved Quantity, Low Stock Threshold, Stock Status
- Purchase: Purchase Type, Enquiry Enabled, WhatsApp Enabled
- Specifications: Material, Stone, Size, Weight, Origin, Certification
- Images: Primary Image, Gallery, Alt Text
- SEO: Meta Title, Meta Description, Keywords, OG Image

**Category Flow**: Admin -> Categories -> Create / Edit -> Name -> Slug -> Description -> Image -> SEO -> Display Order -> Publish

### 7.5 CMS & Media Flow
- **Homepage CMS**: Admin -> Homepage -> Sections -> Edit Section -> Content / Image / CTA -> Enable / Disable -> Reorder -> Preview -> Publish
- **Banners**: Hero, Promotional, Category, Lead Generation.
- **Media**: Upload -> Cloudinary -> Store Metadata -> Select Media -> Use in Product / Banner / Content.
- **SEO**: Global, Homepage, Categories, Products, Guides, Open Graph, Sitemap, Robots.

### 7.6 Admin Dashboard Flow
- **Commerce KPIs**: Total Orders, Today's Orders, Revenue, Pending Payments, Pending Orders, Low Stock, Returns
- **Lead KPIs**: Total Leads, New Leads, Contact Enquiries, Product Enquiries, WhatsApp Clicks
